# C++23 Usage Rules for .JADE

Use C++23 for the compiler infrastructure, but keep the hot JIT graph engine low-level and controlled.

---

## Allowed

| Feature | Use Case |
| :-- | :-- |
| `std::expected<T, E>` | Fallible API (B.2 — no exceptions in JIT) |
| `std::span<T>` | Non-owning views into arenas and side pools |
| `std::print` / `std::println` | Debug logging (NOT in hot inner loops) |
| `std::bit_cast` | Type-punning (e.g., float↔uint32 for fast classification) |
| Deducing this | CRTP-free builder patterns |
| `std::mdspan` | 2-D analysis (e.g., loop nest matrices) |
| `consteval` / `constinit` | Opcode tables, kind names |
| `[[assume(...)]]` | Compiler hints for alignment/non-null |
| Concepts | Constraining templates (`std::integral`, custom `NodeLike`) |
| Ranges | Pass pipelines (`graph.nodes() \| filter(...)`) — non-hot |
| `std::format` | Error message construction |
| Coroutines (`co_await`) | Async compilation job queue |

---

## Forbidden in Hot Paths

| Feature | Why |
| :-- | :-- |
| Exceptions (`-fno-exceptions`) | B.2 — adds unwind tables; throw is O(n) |
| RTTI (`-fno-rtti`) | B.3 — costs cycles, disables devirtualization |
| `std::shared_ptr` | B.4 — atomic refcount, heap control block |
| `std::function` | B.4 — type-erased, heap-allocates captured state |
| `std::regex` | Catastrophically slow, heap-heavy |
| Heap-allocating containers in inner loops | B.1 — use arenas |
| `std::endl` | Flushes stream; use `'\n'` |
| `std::string_view` constructed from temporary | Dangling view |
| `dynamic_cast` | B.3 — uses RTTI |
| `typeid` | B.3 — uses RTTI |
| Variadic virtuals | Disables devirtualization |
| `printf` family | Type-unsafe; use `std::print` |

## Compile Flags

### JIT hot path (`src/jade/ir`, `src/jade/tier*`)

```cmake
target_compile_options(jade_core PRIVATE
    -std=c++23
    -fno-exceptions
    -fno-rtti
    -fno-unwind-tables
    -fno-asynchronous-unwind-tables
    -ffunction-sections
    -fdata-sections
    -Wall -Wextra -Wpedantic
    -Wno-unused-parameter
    -Werror=return-type
    -O3
    -march=native           # for the JIT itself, not the emitted code
)
```

### Tooling / Driver (`src/jade/driver`, tests)

```cmake
target_compile_options(jade_driver PRIVATE
    -std=c++23
    -Wall -Wextra
    -g
    -O0                     # debug builds
    # exceptions and RTTI allowed for the driver
)
```

## Style Rules

- **`[[nodiscard]]`** on every function returning `Result<T>` or `NodeId`.
- **`constexpr`** on every type/size query.
- **`noexcept`** on every hot-path function (we have `-fno-exceptions` so this is implied, but it documents intent).
- **`auto`** only when the type is obvious from the RHS.
- **`enum class`** always, never bare `enum`.
- **Snake_case** for variables and functions; **PascalCase** for types and namespaces.
- **Namespaces**: `jade::core`, `jade::ir`, `jade::tier0`, `jade::tier1`, `jade::tier2`, `jade::tier3`.

## Result<T> Pattern (B.2)

Every fallible API returns `Result<T>` (= `std::expected<T, Error>`). Compilation errors are recoverable:

```cpp
auto result = run_pass(graph, ctx);
if (!result) {
    // abort compilation, fall back to a lower tier, keep running
    log_warn("RUBY pass '{}' failed: {}, falling back to JADE", pass_name, result.error());
    return fallback_to_tier1(graph);
}
```

No `throw`, no `try`/`catch` in the JIT proper. The driver may use exceptions for I/O and argument parsing.

---

## Allocation Patterns (B.1)

Arena-allocate every IR node, every edge, every side-table entry:

```cpp
auto* node = graph.arena().alloc<Node>();      // bump pointer
auto  edges = graph.edge_pool().alloc(n);      // returns EdgeSlice
```

`malloc`/`new` in a hot pass is a CI-checked offense. There is a debug-mode allocator hook that aborts if `malloc` is called from a compiler thread.
